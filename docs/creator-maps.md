# 크리에이터 장소 링크 페이지

현재 변경은 로컬 구현이며 커밋·푸시·배포하지 않았습니다. 기존 홈·모바일 목록 변경을 보존했습니다.

## Supabase 적용

기존 SQL 파일을 삭제할 필요가 없습니다. 기존 프로젝트의 SQL Editor에서 아래 순서로 실행하세요.

1. `docs/sql/add-creator-maps.sql` 전체 실행: 메타데이터, RLS, 소유자 RPC, 커버 버킷과 정리 대기열을 한 트랜잭션으로 적용합니다. 기존 장소·사진·지도·검색 원천은 삭제하지 않습니다. 재실행할 수 있습니다. `DROP POLICY`는 조회 권한 정책 교체이며 장소 데이터 삭제가 아닙니다.
2. `docs/sql/check-creator-maps.sql` 실행: 첫 결과의 DB 용량을 확인하고 나머지 권한·준비 상태가 모두 `true`인지 확인합니다.

적용 파일은 실행 전·후 `pg_database_size`가 450MiB를 초과하면 롤백합니다. 원격 용량과 마이그레이션 이력은 이 작업에서 조회하지 못했습니다. 정상 적용 시 `20261013173542 / creator_maps` 이력을 등록합니다. 기존 이력은 수정하지 않습니다. 기존 경량 장소 검색·역·사진 마이그레이션이 적용된 프로젝트를 대상으로 합니다. 익명 투표 테이블은 없어도 적용됩니다. 이후 익명 투표 마이그레이션을 추가하면 이 적용 파일을 다시 실행해 크리에이터 투표 차단 트리거를 연결해 주세요.

원격 적용 전에는 `/studio`에 준비 안내가 표시됩니다. 홈은 커뮤니티 지도만 표시합니다. 새로운 크리에이터 지도는 프로필·공유 링크로 접근합니다.

## 사용

- 로그인 후 메뉴의 `내 지도` → `/studio`에서 초안을 만듭니다.
- 이름·소개·Instagram 프로필·대표 지도를 편집합니다. 사진·아이디는 기존 `/settings/profile`에서 수정합니다. Instagram 링크는 인증을 의미하지 않습니다.
- 장소 추가는 기존 검색·선택·직접 등록을 재사용합니다. 추천 이유 수정, 위·아래 정렬, 지도 연결 제거를 지원합니다.
- 지도당 장소 200개, 사용자당 보관되지 않은 지도 10개를 제한합니다. 제목 80자, 소개 500자, 추천 이유 5~1,000자입니다.
- 미리보기는 `/studio/[id]/preview`에서 소유자만 접근합니다. 저장·투표·업로드·댓글 등 공개 참여는 비활성화됩니다. 초안의 새 장소는 공개 검색에서 제외됩니다.
- 공개하면 `/u/[handle]`, `/maps/[slug]`로 공유합니다. 제목 변경 후에도 지도 주소는 유지됩니다. 대표 지도는 본인의 공개 지도만 지정할 수 있습니다.
- 공개 지도는 소유자 순서를 기본으로 제공합니다. 방문자의 장소 제안과 주제 투표는 제공하지 않습니다. 저장·사진·댓글·운영 확인·장소 신고는 기존 기능을 사용합니다.
- 공개 지도 정보에서 지도 전체 신고가 가능합니다. 운영자는 기존 관리 화면의 `크리에이터 지도 신고`에서 지도 숨김과 신고 처리 완료를 별도로 수행합니다. 관리자에게는 지도 정보에도 숨김 조치가 제공됩니다.

## 커버와 정리

`creator-map-covers`는 비공개 버킷입니다. 클라이언트 Storage 쓰기를 허용하지 않습니다. 서버가 원본 5MB 이하 JPG·PNG·WebP를 실제 디코딩하고 방향·크기를 보정한 뒤 EXIF 없는 WebP를 저장합니다. 기존 방문자 사진의 3MB 업로드 제한은 유지합니다.

이미지 API는 현재 공개 상태 또는 소유자 권한을 확인하며 `no-store`로 제공합니다. 공개 공유용 `/maps/[slug]/cover`는 초안·보관·숨김 지도를 반환하지 않습니다. 이미 내려받은 이미지는 회수할 수 없습니다.

예약된 경로에 파일이 실제 저장된 후에만 커버를 연결합니다. 교체·제거·보관된 커버와 실패한 업로드는 정리 대기열에 남습니다. 예약·정리는 한 시간 유예로 진행 중 업로드와 충돌을 피합니다. 서버 환경변수를 설정한 터미널에서 다음 명령으로 반복 정리할 수 있습니다.

```sh
node --env-file=.env.local scripts/cleanup-creator-covers.mjs
```

자동 정리 스케줄이나 운영 배포는 추가하지 않았습니다. 비밀키는 브라우저에 전달하지 않습니다.

## 검증

- PostgreSQL/PostGIS의 격리된 `cim_test` DB에서 기존 기능과 크리에이터 권한을 검증했습니다. 스키마·SQL Editor 파일을 두 번 적용하는 재실행 검사도 포함합니다.
- 일반 회원 생성, 타인·비로그인 쓰기 차단, 소유자 전용 초안, 초안 물리 장소 비노출, 범위 검사, 공개 전환, 대표 지도·정렬 검사, 중복 재사용, 연결 제거, 정지 계정·지도 수 제한, 커버 예약·정리 및 관리자 숨김을 검사합니다.
- 단위 테스트는 입력 검증·Instagram 주소 정규화·검색 준비·SEO·이미지 크기와 EXIF 제거를 포함합니다.
- 브라우저 테스트는 API 응답 모형으로 스튜디오 편집·공개·커버 용량 오류와 모바일·데스크톱 화면을 확인합니다. 실제 Supabase 로그인→Storage 업로드 흐름과 구분됩니다.
- 검증용 데이터를 포함한 로컬 DB 크기는 23MB이며, 새 프로필·정리 메타데이터 테이블은 각각 약 32kB입니다. 운영 DB 용량을 나타내는 값은 아닙니다.
- Docker가 실행되지 않아 실제 Storage 업로드·다운로드 통합 검증은 수행하지 못했습니다. 원격 SQL 적용 및 실제 휴대폰 조작도 아직 확인하지 않았습니다.

통계·Instagram 릴스 연동·수익화·여러 지도 통합은 포함하지 않습니다.

현재 로컬 확인: 타입·린트·프로덕션 빌드, 단위 111개, 전체 브라우저 120개(환경별 54개 건너뜀), 기존·크리에이터 DB 권한 테스트 통과. 브라우저 모형과 실제 Storage 미검증의 차이는 위 한계와 같습니다.
