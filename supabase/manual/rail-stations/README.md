# 장소 탐색·방문 UX: Supabase 수동 적용

기존 프로젝트 `cujmxwlwijwomngchwoi`의 **SQL Editor**에서 다음 파일의 전체 내용을 순서대로 실행하세요. 기존 데이터를 초기화하지 않습니다.

1. `01-schema.sql`: 역 테이블·RLS·거리 조회·운영 요약을 추가합니다. 한 번만 실행합니다. 트랜잭션으로 적용하고 마이그레이션 이력 `20261007091810`을 기록합니다.
2. `02-station-data.sql`: 서울·도쿄 역 데이터를 적용합니다. 다시 실행해도 중복되지 않습니다. 두 지역 모두 한 트랜잭션으로 갱신합니다.
3. `03-verify.sql`: 권한 결과가 모두 `true`, 지역별 역 개수가 0보다 큰지 확인합니다. 마지막 결과는 익명 공개 장소 조회 예시입니다.

DB 적용 전에는 앱의 가까운 역 영역에 준비 중 안내가 표시됩니다. 외부 역 데이터 요청은 사용자 조회 경로에서 실행하지 않습니다. SQL 적용 후 새 요청에서 자동으로 활성화됩니다.

## 데이터 범위·출처

서울: 위도 37.35–37.75, 경도 126.75–127.25. 도쿄: 위도 35.45–35.90, 경도 139.45–139.95. 범위 밖은 미지원 지역으로 안내합니다. 범위 안에서 직선거리 2km 안의 지하철·철도역을 최대 3개 표시합니다. 보행 시간·출구 정보는 계산하지 않습니다.

`station-data.json`에 수집일·지역별 원천 ID·현지 이름·종류·좌표를 보관합니다. OpenStreetMap `railway=station/halt` 중 버스·트램·공사/폐지/계획 역을 제외합니다. 현지어 이름을 정규화해 350m 이내의 같은 역 표현을 병합합니다. 데이터의 누락·태그 오류는 있을 수 있습니다.

© [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL 1.0. 데이터 원천 API는 [Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API)입니다. 역 데이터 라이선스는 앱 소스 코드 라이선스와 별개입니다.

## 갱신

```sh
npm run stations:collect
```

두 지역 데이터를 모두 수집·검사한 후 초기 데이터 SQL/JSON을 갱신합니다. 실패하면 기존 파일과 DB 데이터를 유지합니다. 공급자 장애 시 대체 엔드포인트를 시도합니다. 정기 갱신 자동 실행은 설정하지 않았습니다.

생성된 `02-station-data.sql`을 SQL Editor에서 실행하거나, 서버 환경에 Supabase URL과 `SUPABASE_SECRET_KEY`를 설정한 다음 실행합니다:

```sh
node --env-file=.env.local scripts/stations/import.mjs --apply
```

서버 쓰기는 지역별 전체 스냅샷 RPC만 허용합니다. 잘못된 스냅샷은 롤백합니다. 일반 사용자에게는 읽기만 허용하며 계정 위치는 저장하지 않습니다. 성공한 갱신은 지역 revision을 바꾸므로 앱의 24시간 역 캐시를 새 키로 즉시 무효화합니다. 캐시 조회 전에도 공개 장소 여부를 다시 검사합니다.
