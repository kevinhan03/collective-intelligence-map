# 장소 제안 즉시 자동완성과 경량 검색

## 현재 상태와 적용 순서

2026-10-11 운영 DB를 읽기 전용으로 확인했다. DB는 423MB이며, 대량 이름 인덱싱 마이그레이션 `20261010170732`는 이력에 없다. 이전 이름 테이블은 비어 있고 동기화 트리거는 비활성화돼 있다. 이번 구현은 운영 SQL을 적용하지 않는다. 사용자가 SQL Editor에서 아래 **새 파일**을 실행한다. 이전에 복사한 SQL은 사용하지 않는다.

간편 적용은 `docs/sql/apply-lightweight-proposal-search.sql` 하나를 실행한 뒤 `docs/sql/check-proposal-search.sql`로 확인한다. 이 파일은 아래 설정·활성화를 한 트랜잭션으로 묶는다. 단계별 적용을 원하면 다음 순서를 사용한다.

1. `docs/sql/setup-proposal-search.sql`: 정규화·범위 보조 함수와 범위 설정만 준비한다. 이름 테이블을 만들거나 원천을 채우지 않는다. 기존 지역 지도 설정은 유지한다.
2. `docs/sql/activate-proposal-search.sql`: 기존 인덱스를 사용하는 검색·상세·제출 함수를 적용하고, 폐기된 이름 테이블·트리거·배치 함수를 명시적으로 제거한다. `CASCADE`는 사용하지 않으며 예상 밖 의존성이 있으면 트랜잭션 전체가 취소된다. 마이그레이션 이력도 기록한다.
3. `docs/sql/check-proposal-search.sql`: 첫 결과의 세 값이 모두 true인지 확인한다. 다음 결과에서는 DB 전체와 검색 원천의 용량을 확인한다.

**이름 인덱싱 단계는 없다.** 기존 `backfill-proposal-search.sql`은 안내만 반환하고 자동 채우기 스크립트는 실행을 거절한다. 새 활성화 SQL은 작업 전후 DB가 450MB를 넘으면 중단한다. 사용자 장소·사진·원천 행은 변경하지 않는다. 코드도 미커밋·미배포 상태이며 실제 사이트에 보이려면 추후 사용자 지시로 코드 반영이 필요하다.

아직 적용되지 않은 초안 마이그레이션만 경량 내용으로 바꿨다. 이미 적용된 마이그레이션은 변경하지 않았다. 새 DB의 마이그레이션 실행도 대량 원천 복제 없이 같은 설정을 적용한다.

## 입력과 요청

검색창은 2자 이상 입력 변경과 한글 조합 완료 이벤트에서 즉시 검색한다. 타이머나 debounce 대기 시간은 없다. 한글 입력기는 마지막 음절의 조합을 포커스 이동까지 유지할 수 있으므로, 완성형 한글로 끝나고 낱자 자모가 없는 2자 이상 입력은 조합 중에도 즉시 검색한다. 낱자 자모·일본어 등 다른 언어의 조합 중간 문자열은 요청하지 않는다. IME가 완료 뒤 같은 값의 change 이벤트를 보내도 요청을 중복하지 않는다.

검색 중 동일 조건의 버튼·Enter 요청은 합친다. 다른 입력, 2자 미만, 직접 등록 전환, 후보 선택, 계정 변경, 화면 이탈에서는 이전 요청을 취소하거나 결과를 무시한다. 이전 후보는 새 요청 중 보여주되 선택할 수 없다. 실패 시 작업 영역에 오류를 표시하고 직접 등록을 유지한다.

폼 메모리 캐시는 최대 30개, 2분이며 후보 토큰의 만료 5초 전까지만 재사용한다. 사용자·지도·정규화 입력·외부 검색·번역 옵션으로 구분하고 계정 변경·제출·다른 장소 선택 시 초기화한다. 서버는 사용자·권한·지도·입력·옵션·세션이 같은 **진행 중 요청만** 프로세스 내에서 공유한다. 종료·오류 후에는 제거하며 최대 256개까지만 보관한다. 완료된 서버 결과 캐시는 없다. 각 API 요청에서 기존 인증을 먼저 수행한다. 다른 프로세스/인스턴스의 요청까지 합치는 것은 보장하지 않는다.

등록된 장소를 먼저 검색하고 결과가 없을 때만 기존 공급자를 조회한다. 한국의 국가·지역 지도는 Kakao, 일본과 세계 범위는 보유 Overture 원천을 사용한다. 기존 외부 요청 제한을 유지하고 한도 오류에서 자동 재시도하지 않는다. 일본 영어 검색의 번역은 기존 명시적 버튼으로만 실행한다.

## 검색 범위와 DB

- `region`: 설정된 국가와 지도 경계. 날짜변경선을 가로지르는 경계도 지원한다.
- `country`: 설정된 국가 전체. 지도 경계는 초기 화면 표시용이다.
- `world`: 현재 확보된 전체 원천. 보유 지역이 제한된다는 안내를 유지한다.

지도 검색은 현재 공개 상태와 설정을 조회한다. 검색·후보 상세·서명 후보 확인·제출 모두 같은 범위를 검사한다. 활성화 전에는 기존 지역 검색을 유지하고 국가·세계 범위는 준비 상태로 차단한다. 준비 여부는 새 함수의 적용 상태이며 이름 테이블 완성 여부에 의존하지 않는다.

대량 원천의 `search_places_text` GIN과 `search_places_location` GiST를 재사용한다. 새 원천 인덱스·저장 컬럼·이름 테이블·원천 재정규화 작업을 추가하지 않는다. 입력은 NFKC·소문자·연속 공백을 정규화하고, 인덱스 대상 `search_text`에는 함수를 감싸지 않는다. 원천의 기존 이름·별칭·단어 시작 매칭을 사용한다. 원천 자체의 표기·띄어쓰기 불일치를 새 별칭으로 보정하거나 전체 재작성하지 않는다.

이름 정확 일치 → 별칭 정확 일치 → 이름 시작 일치 → 기존 단어 시작 일치 순으로 최대 10개를 반환하고 동률은 원천 ID로 정렬한다. 패턴 특수 문자는 이스케이프한다. 정렬 뒤 상위 10개에만 응답 JSON을 만들어 흔한 검색어의 변환 비용을 줄인다. 등록된 사용자 장소 검색은 기존 RLS·공개/대기 가시성 규칙과 최대 20개 반환을 유지한다.

API 요청/응답과 후보 타입은 기존 형태를 유지한다. 비밀키는 서버에서만 사용하고 검색 원천은 anon/authenticated가 읽거나 쓸 수 없다. 서비스용 검색 RPC는 security invoker와 빈 search_path를 사용한다. 기존 제출·관리자 판정에 필요한 private 함수의 권한 구조를 유지한다.

## 검증과 속도 측정

`npm run check`, `npm run test:db`, `npm run test:e2e -- tests/e2e/workflows.spec.ts --workers=2`로 타입·린트·단위·DB 권한·브라우저·빌드를 확인한다. 검색 순위, 2자/길이 제한, 전각 입력, 패턴 문자, 갱신 반영, 날짜변경선, 상세/제출 범위, SQL 반복 실행을 검증한다.

합성 2만 원천의 비교는 `node scripts/benchmark-proposal-search.mjs`로 실행한다. 실제 원천 규모 검증은 `node scripts/benchmark-proposal-search-live.mjs`로 실행한다. 운영 연결은 READ ONLY 트랜잭션이며 외부 검색 원천만 로컬 `cim_proposal_benchmark_test`에 복사한다. 사용자·사진·인증 데이터를 복사하지 않는다. 테스트용 DB는 운영 스키마·원천을 변경하지 않으며 데이터 삽입은 로컬에서만 한다. 결과와 실행 계획은 Git에서 제외된 `artifacts/proposal-search/`에 저장한다. 로컬 복사본의 응답 시간은 운영 API 응답 시간이 아니다.

서버 `proposal_search_timing` 로그에는 인증·지도·내부·지역·번역·전체 시간과 성공 여부만 기록한다. 검색어·사용자 ID·후보 토큰은 기록하지 않는다. 외부 공급자 지연, 인스턴스 시작 시간과 네트워크는 입력 대기를 없애도 남으므로 SQL 및 코드 반영 후 단계별 시간을 다시 확인한다.

### 이번 검증 결과 (2026-10-11)

타입 검사·린트·단위 테스트 96개·프로덕션 빌드·DB 권한 테스트를 통과했다. 데스크톱/모바일 워크플로 22개를 확인했으며, 타이머를 정지한 상태에서도 조합 완료 즉시 요청되는 것을 검증했다. 이전 응답 무시, 캐시, Enter 중복 방지와 요청 제한 후 직접 등록도 확인했다.

실제 외부 원천 919,940건의 로컬 복사본에서 3회 워밍 실행 중앙값을 비교했다. 운영에서는 읽기 전용으로 기존 RPC와 경량 SQL의 동등한 SELECT를 비교했다. 운영 비교는 DB 왕복 시간이며 인증·후보 서명·외부 공급자·전체 API 시간은 포함하지 않는다.

| 검색 표본 | 로컬 기존 → 경량 | 운영 읽기 전용 기존 → 경량 |
|---|---:|---:|
| ヴィ | 17.97 → 1.41ms | 54.95 → 16.02ms |
| ビンテージ | 11.09 → 0.46ms | 51.53 → 11.41ms |
| Vintage | 12.06 → 1.39ms | 74.87 → 16.98ms |
| カフ | 13.72 → 2.44ms | 62.83 → 19.93ms |
| 결과 없는 표본 | 12.99 → 2.58ms | 137.46 → 24.51ms |

국가/세계 범위의 로컬 경량 검색 중앙값은 0.28~2.68ms였다. 표본 측정값이며 모든 검색어의 지연을 보장하지 않는다. 일반 직사각형 경계는 기존 위치 인덱스의 bbox 판정을 사용하고, 날짜변경선을 넘는 경계에만 추가 포함 판정을 적용했다.

운영 DB 용량은 비교 전후 동일한 443,952,275바이트(pg_size_pretty: 423MB)다. 이번 작업에서 운영 SQL·코드는 적용하지 않았다. 사용자 SQL 적용 후 용량과 세 가지 확인 값을 다시 점검해야 한다.

실제 규모 스크립트의 기본 실행은 원천을 새로 복사한다. `--reuse-local`은 로컬 복사본과 운영 행 수가 같을 때 재사용하며, 같은 행 수가 최신 내용임을 보장하지는 않는다. 복사본은 별도의 로컬 테스트 DB에만 보관된다.
