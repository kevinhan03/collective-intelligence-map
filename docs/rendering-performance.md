# 지도 화면 렌더링 개선

2026-10-18. 모바일 우선으로 적용하며 디자인과 PC의 지도 이동 후 카드 표시 순서를 유지한다. DB, API 요청·응답 형식, 서버 권한 검사와 캐시 무효화는 변경하지 않는다.

## 변경

- 지도 화면·사용자별 댓글/사진 캐시를 공유한다. 동시 요청을 합치고, 30초 이내 데이터는 재사용한다. 오래된 데이터는 재진입 시 표시한 상태로 갱신한다. 사용자 전환 시 저장소를 교체하고 이전 요청을 중단한다.
- 댓글 페이지와 사진 커서를 유지하고, 작성·삭제 후 해당 장소만 갱신한다. 확정된 좋아요·삭제 결과를 이전 조회 응답이 덮어쓰지 않도록 한다.
- 저장·반응·팔로우는 먼저 화면에 반영한다. 요청 실패 시 복구하며 장소·동작별로 중복 요청을 막는다. 요약·상세·목록·핀은 같은 상태를 사용한다. 새로운 서버 장소 데이터를 받으면 서버 값으로 동기화한다.
- 모바일은 현재 카드와 양옆 카드 내용만 렌더링한다. 나머지 슬라이드의 폭은 유지해 스와이프 위치와 순서를 보존한다.
- MapLibre 핀은 클러스터 구성원 ID로 재사용한다. 선택 스타일·숫자·좌표만 갱신하고 없어진 클러스터만 제거한다. 기존 36px 그룹 규칙은 유지하면서 주변 격자만 검색한다.
- 로컬 검색 계산을 공유하고 입력 처리를 지연 가능한 검색 결과 렌더링과 분리한다. 지도 props를 안정화하고 메모화한다. 한글 조합 처리와 서버 검색의 400ms debounce는 유지한다.
- 상세 카드·승인 대기 화면은 필요할 때 로드하며 사진 전처리 코드는 업로드 시에만 로드한다. 상세 로딩 중에도 닫기와 Escape를 지원한다.

## 측정

로컬 프로덕션 빌드, Chromium, 390×844 모바일 화면, 실제 24곳 지도에서 3회 반복했다. 원본 수치와 브라우저 확인 자료는 `artifacts/performance/`에 있다. 외부 지도 스타일 연결 실패가 있어 지도 완성 시간 및 PC 카드 표시 시간은 비교 지표에서 제외한다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 첫 장소에서 렌더링된 카드 내용 | 24개 | 2개 (중간 위치는 최대 3개) |
| 상세 열린 뒤 전체 DOM 요소 중앙값 | 774개 | 511개 |
| 요약 → 상세 과정의 댓글 요청 | 2회 | 1회 |
| 사진·댓글 요청 합계 (목록 썸네일 포함) | 7회 | 5회 |
| PC 비교 시 다운로드된 JS encoded body 합계 | 742,929 bytes | 717,731 bytes |
| 모바일 상세까지 다운로드된 JS encoded body 합계 | 811,212 bytes | 814,392 bytes |

FCP 중앙값은 56ms → 48ms였으나 로컬 환경 변동이 커 일반적인 속도 향상 비율로 해석하지 않는다. 두 버전 모두 50ms 이상 long task가 관측되지 않아 INP 개선을 주장하지 않는다. 상세를 결국 열면 추가 코드도 로드되므로 모바일 전체 JS 용량 감소를 주장하지 않는다.

500개 장소를 격자로 분산한 별도 계산 비교(워밍업 후 500회)에서 그룹 계산은 평균 약 0.80ms → 0.27ms였다. 이는 그룹 함수만의 결과이며 지도 전체 렌더링 시간은 아니다. 500개 장소의 그룹 구성·순서 일치와 카드 내용 최대 3개 제한도 단위 테스트한다.

## 검증 및 경계

- 캐시 중복 요청·만료·오류·재시도·페이지 병합·이전 응답 차단·사용자 격리를 단위 테스트한다.
- 실제 프로덕션 UI에서 API 응답을 모의해 서버 응답 전 반응 표시, 취소, 실패 복구, 요약→댓글 전환 시 추가 요청 없음, 반응 처리 중 route refresh 없음과 브라우저 오류 없음을 확인했다. 실제 댓글이나 반응 데이터는 변경하지 않았다.
- 낙관적 업데이트의 숫자는 마지막 서버 조회 값에 현재 사용자의 변경을 반영한다. 다른 사용자의 동시 변경은 다음 서버 데이터 조회에서 반영한다.
- 최초 전체 E2E 실행에는 이전 UI 기대값(제거된 소개 제목, collapsed 카드 단계, 날짜 조건상 표시되지 않는 목록 배지 등)에 대한 실패가 포함됐다. 지연 로딩 도입으로 생긴 로딩 화면 구분·포커스 문제와 검색 입력 지연 중 추천어 선택 타이밍을 수정했다. 관련 시나리오를 별도로 재검증한다.

### 최초 성능 개선 확인

- 타입 검사·ESLint·프로덕션 빌드 통과, 단위 테스트 153개 통과.
- 검색·렌더링·워크플로 브라우저 테스트 62개 통과, 기기별 제외 10개. 날짜 조건에 의존하는 기존 `mobile list mixed photos` 테스트는 이 실행에서 제외했다.
- 명령: `npx playwright test tests/e2e/map-search.spec.ts tests/e2e/rendering.spec.ts tests/e2e/workflows.spec.ts --workers=2 --grep-invert 'mobile list mixed photos'`.
- 별도 반응형 재검증에서 360/390/430/768/1024/1440/1920px 모두 통과했다.
- 이 최초 실행에는 현재의 요약 카드 선택 흐름, 제거된 저장 버튼 문구, 빈 검색 결과 문구, 날짜에 따른 배지 조건과 맞지 않는 테스트가 남아 있었다. 아래 재검증에서 테스트 절차와 기대값을 현재 요구사항에 맞게 갱신했다.


## 핀 수정 후 재검증 (2026-10-18)

- 클로드가 수정한 MapLibre 핀 코드는 유지했다. 핀을 재사용할 때 라이브러리가 붙인 위치·앵커 클래스를 덮어쓰지 않아야 한다.
- 실제 MapLibre를 로컬 빈 배경 스타일로 띄우는 PC·모바일 회귀 검사를 추가했다. 최초 핀 간 거리, 선택 전후 앵커 위치, 숫자 갱신, 확대, 드래그 이동, 장소 제거 후의 클래스·절대 위치·DOM 재사용을 검사한다. 외부 지도 타일 제공자 상태와 분리한 검사다.
- 늦게 도착한 검색 응답의 자동 선택이 사용자가 직접 연 상세 카드를 닫는 경쟁 조건을 재현하고 수정했다. 직접 선택·카드 열기·닫기·역 선택 시 대기 중인 자동 선택을 취소한다. 지연 응답 테스트는 수정 전 실패, 수정 후 통과를 확인했다. 보류 중인 자동 선택을 수동 선택으로 대체할 때만 검색창을 닫아 자동 선택 완료 시의 동작과 일치시켰다. 일반 탐색 중의 검색창 표시는 유지한다. 검색 참여 흐름과 지연 응답 회귀 검사는 각각 3회 반복해 통과했다.
- E2E는 요약→상세의 현재 흐름, 헤더 저장 아이콘, 더 보기 내 지도 버튼, 접힌 카드 위의 컨트롤을 검사하도록 갱신했다. 배지 검사는 고정 날짜를 사용하고 애니메이션은 생성 기록과 동작 줄이기 설정을 검사해 시간 의존 실패를 줄였다.
- ESLint는 생성된 브라우저 추적 자료·스크린샷·벤치마크 파일을 검사하지 않도록 제외했다.

### 재검증 최종 결과

- 전체 E2E: 146개 통과, 기기별 해당 없음 58개 제외, 실패 0개. 기존 배지·카드 단계 테스트도 제외하지 않고 실행했다.
- 단위 테스트: 47개 파일, 153개 테스트 통과.
- 타입 검사·ESLint·프로덕션 빌드 통과. 핀 수정 코드는 재검증 중 변경하지 않았다.
- 다른 세션의 3100 포트 개발 서버와 충돌하지 않도록 동일한 프로덕션 빌드를 3103 포트에서 실행했다. 최종 검사 시 빌드 이후 변경된 앱 소스가 없음을 확인했다.
