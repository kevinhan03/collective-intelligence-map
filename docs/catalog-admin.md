# 홈 콘텐츠 관리자

> 2026-11-02 운영 DB 적용 완료: `20261102000000_catalog_admin.sql`과 마이그레이션 이력을 운영 프로젝트에 반영했다. 관리자 스냅샷 9개 및 공개 설정 API HTTP 200을 확인했고, 비관리자 접근·직접 수정 차단과 RLS·비공개 이미지 버킷을 검증했다. 기존 지도 레코드의 지문과 장소/지도-장소 개수는 적용 전후 동일했다. 원격 보안 Advisor에서 문제가 없었다. 앱 배포·커밋·푸시는 하지 않았다.

`/admin/catalog`는 기존 관리자 계정으로 사용하는 홈 카탈로그 편집기다. 공개 홈과 `/discover`의 실제 카탈로그 컴포넌트를 재사용한다. 데스크톱은 왼쪽 미리보기와 400px 편집 패널, 좁은 화면은 미리보기/편집 전환으로 제공한다. 모바일 미리보기는 기존 모바일 홈·탐색 구성과 카드 컴포넌트를 사용한다.

## 편집 및 적용

카드를 선택해 표시 이름·카테고리·표시 지역·검색 별칭·대표 이미지·사진 중심을 수정한다. 표시 이름은 홈/탐색 카드뿐 아니라 지도 상세·지도 정보·공유 메타데이터·장소 제안 화면에도 동일하게 반영된다. 원본 DB 제목과 지도 주소는 유지한다. 빈 표시 지역은 기존 지도/지역 요약을 사용한다. 미분류도 유지할 수 있다. 사진은 5MB 이하 JPG/PNG/WebP를 업로드하며, 서버에서 방향을 보정하고 EXIF/GPS를 제거한 WebP로 재인코딩한다. 사진 중심은 별도 창에서 드래그하거나 슬라이더/방향키로 조정한다. 기존 버거 사진의 전체 피사체 표현은 그대로 유지하고 새 이미지로 교체할 때만 표준 크롭으로 전환한다.

여러 지도의 편집 내용은 적용 전까지 이 탭의 `sessionStorage`에 관리자별로 남는다. 새로고침 후 복원되며 다른 카드로 전환해도 유지된다. 탭을 닫으면 사라진다. 로그아웃/계정 변경 후 다음 앱 화면에서 다른 계정의 임시 변경을 제거한다. 저장소가 차단되면 화면 내 편집만 가능하다는 안내를 표시한다. 별칭은 Enter 또는 ‘추가’로 확정한다.

‘변경사항 적용’은 변경한 지도 전체를 한 DB 트랜잭션으로 저장한다. 기준 버전이 하나라도 다르면 HTTP 409로 전체 적용을 취소한다. ‘최신 내용 확인’ 후 충돌한 지도의 ‘이 지도 되돌리기’를 눌러 최신 값을 기준으로 다시 편집한다. 적용 실패 시 임시 변경을 유지한다. 적용 성공 후 새 스냅샷 조회만 실패했다면 적용 완료와 새로고침 필요를 구분해 알린다.

지도 주소, 원본 제목, 장소, Hype/저장 기록은 바꾸지 않는다. 미리보기에서 반응 컨트롤은 비활성화된다. 공개 지도는 ‘지도 열기’로 새 탭에서 확인한다. 인기순은 최근 7일 Hype 기준을 그대로 사용한다. 추천 지정과 수동 정렬은 편집 대상이 아니다. 기존 모바일 추천 설정/순서는 보존된다.

## 데이터·권한

- `public.catalog_settings`: 지도 ID, 노출 메타데이터 JSON, 버전, 최종 수정자/시각. 공개 SELECT는 공개 커뮤니티 지도의 `map_id,value,version` 컬럼만 허용한다. 최종 수정자와 감사 기록은 공개하지 않는다.
- `private.catalog_images`: 관리자 소유 임시 이미지, 지도 연결, 24시간 만료, 업로드/사용/정리 상태.
- `private.catalog_audit`: 적용된 변경의 전후 값과 수정자/시각. 일반 클라이언트는 읽거나 수정하지 못한다.
- 기존 `catalog-config.ts` 값을 마이그레이션의 초기 데이터로 복사한다. 설정이 없는 새 지도는 원본 표시와 기존 이미지 대체 처리를 사용하며, 처음 적용할 때 버전 0으로 생성한다.
- 마이그레이션 전 공개 홈은 기존 코드 설정을 사용한다. 관리자 화면은 준비 안내를 표시한다. DB와 Storage를 먼저 준비한 뒤 앱을 배포한다.

API는 관리자 전용 `GET/POST /api/admin/catalog`와 `POST /api/admin/catalog/images?mapId=...`를 제공한다. 이미지 조회는 `/api/catalog/images/[id]`이며, 현재 공개 지도에 적용된 사진 또는 소유 관리자의 만료 전 임시 사진만 읽을 수 있다. 앱은 서명 URL이나 Storage 직접 다운로드 URL 대신 권한을 확인하는 이미지 경로를 사용한다. 이미지 응답은 `private, no-store`이고 Next 이미지 최적화 캐시를 거치지 않는다.

모든 쓰기는 관리자 권한과 동일 출처를 확인한다. DB에서도 정지되지 않은 관리자만 전용 RPC를 실행할 수 있다. 공개 RPC는 `SECURITY INVOKER`이며 권한 검사를 수행하는 내부 함수만 비공개 스키마에서 실행된다. 일괄 적용은 지도를 일정한 순서로 잠그고, 이미지도 잠금/상태 검사 후 연결한다. 적용 후 `public-community` 캐시를 즉시 무효화한다.

## 로컬 검증과 운영 반영

마이그레이션: `supabase/migrations/20261102000000_catalog_admin.sql`. 기존 지도 데이터를 변경하지 않고 노출 설정만 초기화한다. 최초 로컬 구현 후 사용자의 별도 요청으로 운영 DB 적용을 완료했다. 커밋·푸시·앱 배포는 하지 않았다.

로컬 Supabase를 준비한 후 `npm run local:setup`으로 환경을 생성한다. 기본 3000 포트가 사용 중이면 별도 빌드 디렉터리를 사용한다.

```sh
NEXT_TEST_BUILD=true NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3001 PORT=3001 npm run dev:local
npm run test:catalog:live
npm run test:db
```

프로덕션 모드에서 3001 포트로 검증하려면 빌드 때도 같은 사이트 주소를 지정한다. `NEXT_PUBLIC_SITE_URL`은 빌드에 포함되므로 시작할 때만 바꾸면 동일 출처 검증과 맞지 않을 수 있다.

```sh
NEXT_TEST_BUILD=true NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3001 npm run build:local
NEXT_TEST_BUILD=true NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3001 PORT=3001 npm run start:local
```

`test:catalog:live`는 로컬 API/DB만 허용하고 임시 관리자·회원 세션으로 실제 편집/충돌/Storage/공개 반영/모바일 배치를 검증한다. 종료 시 기존 카탈로그 값을 복구하고 테스트 계정을 제거한다. 이미지는 정리 대상으로 남을 수 있으므로 로컬 정리 명령을 실행한다. 운영 DB에서 실행하지 않는다.

## 이미지 정리

```sh
npm run catalog:cleanup -- --local
# 원격 운영 대상은 명시적으로 실행할 때만 사용:
npm run catalog:cleanup
```

정리 작업은 24시간이 지난 미적용 이미지와 교체된 이미지 중 어느 설정에서도 참조하지 않는 파일만 대상으로 삼는다. DB에서 먼저 `deleting`으로 선점하므로 적용 요청과 경합해도 사용 중인 파일이 삭제되지 않는다. Storage 삭제 후 DB 기록을 확인 처리하며, 실패 시 재시도할 수 있도록 기록을 남기고 명령이 실패 상태로 종료된다. 원격 자동 스케줄은 이 변경에서 설치하지 않는다. 운영 반영 시 매일 실행하는 스케줄을 별도로 연결한다.

만료된 임시 이미지는 재선택해야 한다. 관리자 화면의 ‘사진을 다시 선택해 주세요’ 메시지에서 이미지 변경을 다시 수행한다. 임시 변경 복원 기간과 이미지 보관 기간은 별개다.
