# 로그인 전용 투표와 보안 패치 운영 안내

## 변경 정책

신규 장소 투표는 로그인 계정에서만 받는다. 비로그인 투표 버튼은 로그인으로 연결하고, 성공 후 같은 지도·장소로 돌아온다. 로그인 자체로 표를 자동 등록하지는 않는다. 세션 만료로 401을 받으면 낙관적 변경을 되돌리고 로그인으로 연결한다.

기존 익명 표는 삭제하거나 집계에서 제외하지 않는다. 기존 쿠키를 가진 사용자의 선택 상태 조회와 로그인 시 계정 이전도 유지한다. 계정에 이미 표가 있으면 기존 병합 규칙에 따라 더 최근 표 하나만 남는다. 따라서 중복 표가 정리되는 경우 집계가 감소할 수 있으며, 전체 익명 표를 제거하는 정책 변경은 아니다. 쿠키를 잃어버린 과거 익명 표는 집계에 남는다.

이 정책은 과거 조작 표와 다중 계정 투표를 소급 제거하지 않는다.

## 준비된 반영 단위

- 앱: 익명 투표 경로·쿠키 발급 제거, 로그인 복귀 및 세션 만료 처리, JSON 스트리밍 제한, 관리자 비밀번호 바이트 비교.
- DB: `supabase/migrations/20261103172038_disable_new_anonymous_votes.sql`. CLI가 생성한 버전 이름을 사용한다. 과거 익명 표는 건드리지 않고 신규 기록 RPC 및 서버 역할의 INSERT·UPDATE 권한을 차단한다. 함수 소유자가 호출해도 기록 함수는 거부한다.
- 기존 복구 SQL도 같은 정책으로 수정했다. `docs/sql/repair-anonymous-votes-and-search-helpers.sql` 재실행으로 익명 쓰기가 다시 열리지 않으며, 대응 확인 SQL도 신규 쓰기 차단을 검사한다.
- 개발 도구: Vitest 5.1.0, shadcn 4.23.0, Next 및 eslint-config-next 16.4.4와 필요한 전이 패치. CI는 운영 의존성 전체와 전체 의존성의 높음·치명적 경고를 차단한다.

## 원격 반영 순서 — 별도 실행 필요

이번 작업에서는 원격 DB 적용과 배포를 수행하지 않았다. 후속 반영 시 다음 순서로 진행한다.

1. 운영 DB의 익명 표 찬반 집계·행 수를 비공개 운영 기록에 남기고 백업 상태를 확인한다. 사용자 토큰 해시를 로그에 복사하지 않는다.
2. 로그인 전용 앱을 먼저 배포해 익명 요청을 401로 차단한다. 롤링 배포의 이전 인스턴스가 남아 있는 시간을 최소화한다.
3. 새 마이그레이션을 즉시 적용한다. 이 단계까지 마쳐야 이전 인스턴스나 구버전 서비스 코드의 익명 DB 쓰기도 차단된다. 과거 마이그레이션 전체를 재실행하지 않는다.
4. 확인 SQL `docs/sql/check-anonymous-votes-and-search-helpers.sql`의 첫 결과가 모두 true인지 확인한다. 기존 익명 집계가 유지되는지 비교한다. 동시 로그인 병합·장소 병합에 따른 정상 변동은 구분한다.
5. 비로그인 투표 POST 401, 다른 출처 403, 로그인 계정의 투표·취소, 모바일/데스크톱의 장소 복귀를 확인한다. 401 응답에 익명 쿠키가 생기지 않아야 한다.
6. 로그인 성공 후 기존 표 이전과 공개 수치 표시를 확인하고, 권한이 있는 계정으로 운영 Supabase Security Advisor를 다시 실행한다. 401·403·413·500의 비정상 증가를 확인한다.

DB 마이그레이션은 앱 선반영을 전제로 한 순서다. 보안 대응을 위해 DB를 먼저 적용해야 한다면 구버전 앱의 비로그인 투표가 일시적으로 오류를 보여줄 수 있으므로 앱 전환을 바로 이어서 수행한다.

롤백 시 익명 쓰기를 다시 열지 않는다. 가능한 한 수정 배포로 복구하고, 불가피한 앱 롤백에서도 DB의 차단 정책은 유지한다. 과거 익명 기록을 삭제하는 작업은 별도 정책 결정 없이는 수행하지 않는다.

## 의존성의 남은 경고

2026-11-04 검사: 운영 의존성 0건, 전체 높음·치명적 0건. 중간 19개·낮음 2개 패키지 항목은 아래 두 원인과 그 상위 의존성으로 집계된다.

| 원인 | 현재 제약과 영향 | 후속 조치 |
| --- | --- | --- |
| minimatch glob 처리 DoS | 11.0.1부터 수정됐으나 ESLint 도구는 3.x, typescript-eslint·ts-morph는 10.x를 요구한다. 신뢰하지 않는 glob 패턴을 개발 도구에 전달하는 경우 CPU·메모리 소모 위험이 있다. 운영 의존성 트리에는 포함되지 않는다. | 상위 도구의 호환 업데이트·백포트를 추적한다. 3.x/10.x를 11.x로 강제 덮어쓰는 override는 사용하지 않는다. |
| deepmerge prototype poisoning | shadcn 및 registry가 사용하는 4.3.1이 검사 시점의 최신 버전이고 수정 릴리스가 없다. 외부 registry·객체 병합 입력을 신뢰할 수 있는 출처로 제한해야 한다. 운영 앱의 직접 사용 경로는 없다. | 보안 패치나 상위 라이브러리 교체 릴리스가 나오면 업데이트한다. |

근거: [minimatch 유지관리자 공지](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249), [deepmerge 보안 공지](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). npm의 영향 패키지 수는 서로 다른 취약점 수와 다르다. 무관한 업그레이드, 강제 메이저 변경, 과거 버전으로의 다운그레이드는 수행하지 않는다. 정기 보안 워크플로와 Dependabot으로 후속 패치를 추적한다.
