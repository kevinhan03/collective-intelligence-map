# 지도 전체 공개 장소 검색

SQL Editor에서 `docs/sql/add-map-public-search.sql`을 실행한 뒤 `docs/sql/check-map-public-search.sql`을 실행합니다. 권한·정규화 확인의 세 열은 모두 true여야 합니다. 기존 역 스키마와 데이터는 재사용하며 장소 데이터 초기화는 하지 않습니다. 적용 파일은 재실행 가능하고 `20261008112237` 마이그레이션 이력을 기록합니다.

## API

`GET /api/maps/[id]/search`는 로그인 없이 공개 장소만 검색합니다. `q`(최대 100자), `stationId`, `region`, `sort`, `offset`, 가까운 순의 `lat`·`lng`를 받습니다. 페이지 크기는 20입니다. 응답의 `items`는 기존 장소 식별자를 유지하고 선택 역이 있으면 `station_distance_m`가 추가됩니다. `total`, `hasMore`, `suggestions`, `station`, `stationsStatus`, `mode`도 반환합니다. 응답은 no-store로 제공됩니다.

문자 폭·대소문자·공백을 정규화하고 각 단어가 이름·주소·분류(표시명 포함)·추천 이유·지역 중 하나에 포함되는 AND 검색입니다. 장소명 정확 일치, 시작 일치, 부분 일치, 다른 필드 일치 순이며 동률에는 기존 주제 추천 점수와 장소 ID를 사용합니다. 다른 정렬은 전체 검색 결과에 먼저 적용한 뒤 페이지를 나눕니다.

역 이름은 자동완성 후보를 찾는 데 사용됩니다. 후보 선택 전에는 반경 필터가 적용되지 않습니다. 선택 후 역 ID와 2km 직선거리로 범위를 고정하며 같은 이름의 역은 종류·지역으로 구분합니다. 지도에 공개 장소가 2km 이내에 있는 역만 후보가 됩니다. 역 거리 계산과 데이터 제공 범위는 기존 서울·도쿄 역 데이터를 따릅니다.

## 호환·실패 처리

검색 RPC가 아직 없으면 클라이언트가 현재 불러온 장소만 검색하고 `현재 불러온 장소 내 검색`을 표시합니다. 이 상태에서는 역 검색을 제공하지 않습니다. 일반 네트워크·DB 오류는 범위를 축소한 성공 결과로 처리하지 않고 재시도를 안내합니다. 기존 목록과 상세 기능은 유지됩니다. 새 검색·정렬이 이전 검색과 페이지 요청을 취소하며 SQL에서는 요청자와 관계없이 공개 상태를 검사합니다.

## 검증

`npm run test:db`는 격리된 `_test` DB에서 마이그레이션·525개 장소의 페이지 검색·공개 권한·2km 경계·역 명시 선택·SQL/TypeScript 정규화 일치를 검사합니다. `npm run check`와 `npm run test:e2e`로 단위 검사와 데스크톱·모바일의 자동완성·페이지 이동·취소·실패 복구·화면 전환을 확인합니다. 운영 DB 적용은 사용자가 SQL Editor에서 수행하며 운영 데이터에 대한 자동 쓰기·배포·커밋·푸시는 하지 않습니다.
